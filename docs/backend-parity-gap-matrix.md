Generated by scripts/backend_gap_matrix.py (AST coverage of the persistence ABC vs each backend). 2026-06-13.

## Summary (111 ABC repository methods)
| backend | IMPL | STUB | RAISE | absent | % complete |
|---|---|---|---|---|---|
| postgres | 111 | 0 | 0 | 0 | 100% (reference) |
| sqlite | 111 | 0 | 0 | 0 | 100% (reference) |
| oracle | 98 | 9 | 4 | 0 | 88% (sessions/oauth/consultations incomplete) |
| db2 | 87 | 1 | 1 | 22 | 78% (inherits oracle gaps; oauth/sessions schema split) |
| mysql | 20 | 1 | 1 | 89 | 18% (only Memory partial + CompressionQueue) |

## Why it diverged
- postgres + sqlite are the original complete implementations (the reference contract).
- oracle was ported but left Sessions/OAuth/Consultations as stubs/raises AND mis-ported the oauth schema (token-hash design instead of the PG OIDC design the route code targets — see mem_1781325370745_d6cba6).
- db2 derives from OracleBackend, so it inherits oracle gaps + the oauth/sessions schema split.
- mysql was barely started (~18%): only MemoryRepository (partial) + CompressionQueueRepository.
