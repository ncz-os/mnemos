# MNEMOS 7.2.1 — backport candidate inventory

Status: inventory only (no code changes). Prepared for the 7.2.1 patch release,
which is cut from `stable/7.2.y`.

## Scope and rules

- 7.2.1 may contain **only bug fixes already on `master`**, cherry-picked with
  `git cherry-pick -x` so the mainline commit is named in the trailer.
- **No database migration** may be required. `master` carries
  `0073_model_registry_repository_phase2` and `0073_memory_acl`; nothing
  backported may need either. Migrations ship only in minor releases.
- Range walked: every **non-merge** commit in `v7.2.0..master`
  (**218** commits; 336 including merges).
- `stable/7.2.y` is currently **8 commits** past `v7.2.0`; the version string is still 7.2.0.
- Reference points: `v7.2.0` = `26dd8f12`,
  `master` tip = `e0e75940`,
  `stable/7.2.y` tip = `ba55604c`.

### Method

Each commit was classified from its subject, body and changed-file list. FIX
candidates were then trial-picked with `git cherry-pick -x` onto a **throwaway
scratch branch** (`scratch/721-pick-test`) cut from `stable/7.2.y` in a scratch
worktree under the job workspace. Picks were attempted **cumulatively** on the
scratch branch; conflicting picks were aborted and skipped, so a later result
assumes only the earlier *clean* picks are applied. The recommended order below
is derived from the dependency notes, and the trial approximated it. The scratch
branch and worktree are discarded after the trial; `stable/7.2.y` and every other
existing branch are untouched. Results: `clean`, `conflict (files)`, or
`empty (already applied)` when the change is already present on the target.

A recurring wrinkle: the 2026-11-15 history rewrite re-landed several fixes, so
some post-tag commits are **duplicates** (identical patch-id) or their **net
effect is already inside `v7.2.0`**. Those are flagged below; `git cherry`
alone does not detect them because the surrounding context differs.
