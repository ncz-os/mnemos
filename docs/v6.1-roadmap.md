| # | Item | Source | Effort |

**Item 15 detail:**

NATS already deployed for federation (`mnemos/nats/` dir). Adds KV store on same bus to replace Redis primitives:

| Primitive | Today (Redis) | v6.1 (NATS KV) |
|---|---|---|
| `RedisRateLimiterPool` | `INCR + EXPIRE` per key | KV bucket with TTL + atomic add via subject CAS |
| `RedisCircuitBreakerPool` | key→state with TTL | KV value with TTL; watch subject for state-change broadcast |
| `RedisConcurrencyLimiterPool` | distributed semaphore via INCR/DECR with TTL backstop | KV CAS or NATS pub/sub-coordinated counter |
| `app.state.cache` (currently dead, never used) | Redis reserved slot | **either retire OR plug into NATS-backed L1 cache for memory.fetch_by_id** |

**Acceptance for #15:**
- Drop-in `mnemos/core/resilience.py` ABC: `ResilienceBackend` with `Redis` + `NatsKV` impls
- Config knob `MNEMOS_RESILIENCE_BACKEND=redis|nats|postgres-unlogged`
- 3-way perf comparison artifact <archived bench artifact>
- Multi-worker correctness proof (4 workers × 100 checks → no drift)
- p99 latency ≤5ms on NATS path at 200 ops/sec MNEMOS-realistic load
- Default ships as `redis` for upgrade compat; `nats` becomes recommended customer default after the bake

**Why this matters strategically:**
- Removes Redis as a deploy dependency (1 less service on customer cixmini)
- Federation + resilience coordinate on same bus
- Cross-region cluster story improves (NATS clusters across DCs natively)
- "MNEMOS runs on cixmini with Postgres + NATS only" = clean customer pitch

### Db2 native dialect port (drop Oracle Compatibility Mode dependency)

> **Full plan**: see [`docs/native-db2-port-plan.md`](native-db2-port-plan.md) — ~580 lines of file-by-file requirements, type + SQL idiom mapping tables, test strategy, 3-phase sequencing, risks + validation checklist. The summary below stays for roadmap-level overview.

Today's `Db2Backend` (`mnemos/persistence/db2.py`) ships on top of Db2's Oracle Compatibility Mode (`DB CFG ORA_COMPATIBILITY ON` + `ENABLE_ORACLE_COMPATIBILITY=true`). `Db2MemoryRepository` and the other repository classes subclass their Oracle counterparts and inherit Oracle SQL verbatim, with `_Db2AsyncCursor.execute` rewriting tokens at query time. `Db2MemoryRepository.semantic_search` is the one method that already emits native Db2 SQL directly so the DiskANN index actually engages — everything else still travels through the compat layer.

This was the fastest path to a working Db2 backend with same-ABC parity. It has a real cost: parse-time translation overhead per query, optimizer cannot see native dialect tokens directly. The bench-v4 numbers include this overhead.

|---|---|---|---|---|
| **44** | **Native Db2 dialect port** — drop Oracle subclassing + cursor translation in favor of hand-written native Db2 SQL with native `VARBINARY`/`BIGINT`/`CLOB` typing and `MERGE INTO` upserts. A/B native vs Oracle-compat on the same DiskANN index. Ship whichever is faster as the v6.x default. Doc disclosure already says native port is on the roadmap so IBM-eng reviewers know we know. | IBM-eng adversarial audit 2026-05-21 | **P1** (credibility-critical for Db2 partnership; cannot claim 12.1.5 perf parity until measured) | 2-3 weeks |

## Federation feature backlog (added 2026-05-23)

### F-1: Copy embeddings via federation feed

**Problem:** Federation `/v1/federation/feed` pulls memory rows (id, content, metadata, etc.) but the `embedding` VECTOR column is NULL on federated rows at the replica. Replicas (CERBERUS, ACHILLES) cannot serve vector search locally without recomputing embeddings — duplicating work the primary already did.

**Proposed:** Include `embedding` BLOB/BASE64 in the federation feed payload (serialize VECTOR → bytes). Receiver imports the column verbatim. Optional opt-in via peer config `copy_embeddings: true` (default OFF for bandwidth-sensitive deploys).

**Acceptance:**
- Federation pull populates `embedding` column on replica matching primary's vector
- A peer setting toggles inclusion
- Bandwidth impact documented (768-dim float32 = 3 KB/memory; 8235 memories = ~25 MB initial replication cost)
- Test: CERBERUS replica after full sync has 100% embedding coverage matching PYTHIA primary

**Surface:**
- `mnemos/api/routes/federation.py` — feed serialization adds embedding field
- `mnemos/persistence/*Federation*Repository` — `fetch_memory_page` returns embedding bytes
- Peer schema — add `copy_embeddings` bool column to federation_peers
- Migration: alter federation_peers table (PG + Oracle + Db2 + SQLite)
- New parity tests + docs

**Priority:** MEDIUM (HA standby + replica search both benefit). Could land in v6.1 mid-cycle.

**Source:** Discovered during 2026-05-23 CERBERUS federation standup — confirmed NULL embeddings on `fed:pythia:*` rows.

**Detailed design:** `docs/v6.1-federation-embeddings-copy.md` (5-step F-1.1..F-1.5 implementation sequence, model-match enforcement spec, bandwidth math, telemetry surface).

**Status (2026-05-23):**
- F-1.1 schema landed: `db/migrations/{,_oracle,_db2}/0028_federation_peers_copy_embeddings.sql` (commit 614d483)
- F-1.2..F-1.5 hive-queued: `019e5764-6c91`, `019e5764-6cd6`, `019e5764-6d1a` (consumer + telemetry job not yet filed)
