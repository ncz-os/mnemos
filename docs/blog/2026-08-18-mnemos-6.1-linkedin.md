We shipped MNEMOS 6.1 this week. It is a patch line — no new subsystems — and
it is the most useful release we have done, because nearly every fix in it is
the same bug wearing different clothes:

**The guard existed. It was correct. It never ran on the path that failed.**

A few examples from this cycle:

→ Rate limiting had a fail-open handler. It was registered for one exception
type, and the middleware resolves handlers by *exact* type. When the store went
away it raised a different error, missed the lookup entirely, and returned 500
on every route — including /health. The test passed the whole time, because it
called the handler directly instead of making a request.

→ Federation reported `{"pulled": 0}` successfully for three months. Memories
were written with permissions the feed's own visibility gate excluded. A green
check mark over a system doing nothing.

→ Two nodes both reporting the same embedding model at the same dimensionality
turned out to be **0.778 cosine apart** — one had been started with the wrong
pooling mode. For scale, changing quantisation moved vectors by 0.006. The
thing everyone worries about was 30× smaller than the thing nobody was
looking at.

The habit that catches this class is cheap and uncomfortable: **make the test
fail against the unfixed code first.** Not "assert the function behaves" —
assert the system is broken before your change and fixed after. If it passes
both ways, it is not testing what you think.

The second habit: when a measurement says something impossible, suspect the
instrument before the product. Twice this cycle the measurement was wrong.
