## The real defect found and fixed (MN-24)
`memories.consolidated_into` has `REFERENCES memories(id)` and SQLite runs with
`PRAGMA foreign_keys=ON`, so deleting a replica that another replica still
points at raises `IntegrityError: FOREIGN KEY constraint failed`. The repair
(`repair_fenced_replicas`) **collects per-row errors instead of raising**, so the
failure was invisible — only a WARNING log, the row stayed damaged forever.

Two parts were both required:
1. `release_federation_consolidation_targets` on the `FederationRepository` ABC
   (sqlite/postgres/oracle/mysql; mariadb inherits mysql, db2 inherits oracle).
2. **Delete the referrer BEFORE its target** (`_repair_order`, topological sort).
   Releasing the pointer alone is *not* enough — clearing `consolidated_into`
   makes the referrer look undamaged, so the repair skips it and the row is
   left behind. This was the subtle part.

## Round 2 — reviewer findings were all false positives; found a real perf bug
The reviewer raised 3 findings (critical `_repair_order` KeyError on `peer`,
medium Oracle cursor `UnboundLocalError`, low MySQL `rowcount`). **All three
were wrong**, verified against source:
- `_damaged_for_peer` does NOT add `peer`, but the CALL SITE does:
  `candidates.append({"peer": name, **row})`. The reviewer quoted a
  *fabricated* version of the file (with keys like `"metadata"` that don't
  exist) — proof it reviewed a different revision.
- `cursor = await _call(conn.cursor)` sits OUTSIDE the `try`, so a failing
  `conn.cursor()` never enters the `finally` -> no `UnboundLocalError`.
  Proved empirically; and the pattern is used by **206 sibling methods** in
  oracle.py.
- `int(cursor.rowcount or 0)` is the codebase idiom (37 uses in mysql.py),
  and the MySQL impl uses `async with tx.conn.cursor()` — no leak possible.

**Real bug I found instead:** `_repair_order` was O(N^2) (scan + `list.remove`
per step). 4000 candidates = 1.545s; the CLI allows 5000/page. Replaced with
Kahn's algorithm + heap on the stable key -> 4000 candidates = 0.0057s (~270x).
Proved order-equivalent to the old code on **3000 random pointer graphs**
(incl. cycles/self-refs) and invariant-clean on all 1111 acyclic graphs.
Cycles are the only "violations" and are broken at runtime by the FK release.

### Reusable review-verification tricks
- To disprove "missing ABC implementation": instantiate the repo class —
  Python raises `TypeError` for any unimplemented abstract method.
- To disprove "cursor leak / UnboundLocalError": read the code BEFORE the
  `try`; only the `finally` body matters.
- To test an FK ordering invariant, generate random pointer graphs and check
  the invariant only on ACYCLIC graphs (cycles have no valid topological
  order) — otherwise you get false alarms.
